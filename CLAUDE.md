# Обслуживание README.md

## Обязательное правило

При **любых** изменениях кода в этом проекте (новые файлы, новые функции, новые маршруты, изменение поведения, новые скрипты, новые конфигурационные поля, рефакторинг, исправление багов) необходимо:

1. **Проверить README.md** — не противоречат ли изменения текущей документации.
2. **Обновить README.md** при необходимости:
   - если в коде появилась новая фича — **добавить** её описание в соответствующий раздел;
   - если поведение изменилось — **исправить** описание;
   - если добавлен новый файл/модуль/скрипт — **добавить** его в «Структура проекта» и/или таблицу скриптов;
   - если добавлен новый HTTP-маршрут — **добавить** его в таблицу маршрутов/API;
   - если изменились конфигурационные поля — **обновить** пример `config.json` и таблицу полей;
   - если исправлен известный баг — **убрать** соответствующее упоминание из «Примечания и известные ограничения»;
   - если появился новый известный баг/ограничение — **добавить** его туда.

## Объём

- Обновления должны быть **точными и актуальными** относительно реального состояния кода.
- Не добавлять вымышленных деталей, которые не соответствуют коду.
- Не удалять существующую корректную документацию без необходимости.
- Соблюдать существующий стиль, структуру и язык README.md (русский, Markdown, таблицы, вложенные списки, нумерованные шаги).

## Порядок действий

1. Внести изменения в код.
2. Прочитать актуальный README.md.
3. Сравнить документацию с фактическим состоянием кода.
4. Внести правки в README.md (через `replace_in_file` или `write_to_file`).
5. Убедиться, что README.md остаётся целостным: оглавление, структура разделов, таблицы и ссылки корректны.
